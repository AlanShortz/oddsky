# sky1 bug: neighbouring stars' NEOWISE visits were merged (found 2026-10-28)

**What.** `oddsky.sky.neowise_pixel.visits()` started a new source with
`df["allwise_cntr"].ne(df["allwise_cntr"].shift())`. `Series.shift()` upcasts int64 to float64, and AllWISE
cntrs are 19-digit integers: at ~1e18 consecutive float64 values are 256-512 apart, so neighbouring cntrs compare
*equal*. After sorting by (cntr, mjd), star B's first visit (2014) followed star A's last visit (2024) with a
negative time step, so no visit gap was found either, and B's first-visit detections were medianed into A's last
visit. The merged visit carries A's cntr and sorts first or last depending on whose detections dominate its median
time. Every star lost its true first visit; most stars had one contaminated visit.

**How it was found.** A "vanishing infrared excess" query on `sky1_features` returned 1,746 stars. Re-fetching the
shortlist from IRSA showed four of five unchanged. For AllWISE 2851042501351049620 the sky1 last visit had 27 W1 /
24 W2 detections and W2 = 11.02; the raw year-11 Parquet has 15 detections at W2 = 9.79. Re-running `visits()` on the
whole pixel lost the star's visit; on the star alone it was right.

**Fix.** Compare the cntr column as int64 (`np.r_[True, cn[1:] != cn[:-1]]`). Regression test
`tests/test_sky.py::test_neighbouring_19_digit_cntrs_stay_separate` uses real 19-digit cntrs; it fails on the old
code and passes on the new.

**Impact, measured by re-running three real pixels both ways** (`impact.py` in the research notes):

| pixel | stars | n_visits changed | testable photospheres old -> new | afterglow flags old -> new |
|---|---|---|---|---|
| 9840 (ASASSN-21qj) | 55,818 | 84% | 9,072 -> 14,559 | 2 -> 2 |
| 9235 | 32,983 | 70% | 2,123 -> 4,688 | 0 -> 0 |
| 11422 | 17,858 | 68% | 1,799 -> 2,482 | 0 -> 0 |

- The afterglow flag needs two consecutive risen visits, so a single bad visit rarely made or killed a flag, and every
  H-0002 survivor (OS-0013, OS-0014) was vetted on light curves re-fetched from IRSA by position. **They stand.**
- **Completeness was not fine.** The contaminated visit inflated `base_std_w2`, so more stars pass the "testable
  photosphere" cut after the fix: +38% to +121% on the three test pixels, +35% over the whole sky (sky2, below). H-0002
  tested about three-quarters of the stars it could have.
- The 0.02-0.03 mag late-mission W2 drift of quiet photospheres is real (median 0.026-0.034 with the fix).
- Single-visit features (`w2_ptp`, `w2_end`, `color_end`, `w1_ptp`) and `sky1_lightcurves` are unreliable.
  Any query on them must be re-done after a re-run.

## sky2: the fixed re-run (2026-10-28)

Authorised by the user and run the same day: fixed code uploaded as `gs://oddsky-sky-br3c3-data/code/neowise_pixel_v2.py`
(sky1's `code/neowise_pixel.py` left untouched), job spec `infra/gcp/sky2.json` (`make_job.py ... sky2 neowise_pixel_v2.py`),
Cloud Batch job `oddsky-sky2`, 508/508 tasks succeeded in ~1 h 50 min, outputs `runs/sky2/`, BigQuery external tables
`sky.sky2_features`, `sky.sky2_candidates`, `sky.sky2_lightcurves`. (`sky2_candidates` points at the consolidated
`runs/sky2/candidates_all/all.parquet`, 314 rows with ra/dec: an external table over the per-pixel files autodetected a
schema without ra/dec, because empty pixel files came first.)

| full sky (10,145 pixels) | sky1 | sky2 |
|---|---|---|
| star rows | 176,852,114 | 164,710,052 |
| with >= 8 visits | 114,745,763 | 114,721,010 |
| testable photospheres | 18,080,793 | **24,470,530 (+35%)** |
| afterglow flags | 224 | **314** |
| H-0006 vanishing-dust flags (query #3) | 108 | **24** |

- The 12 M extra star rows in sky1 were mostly phantoms: sparse sources given a light curve by a neighbour's detections.
- H-0006's survivor (AllWISE 2417031901351019982, J160708.51-320101.1) still fades in sky2 (color_end -0.40, w2_end +0.80)
  but no longer passes the quiet-baseline cut: with its real first visit restored, base_scatter_w2 = 0.137 (cut 0.05).
  Its vetting used IRSA light curves and is unaffected; its *selection* depended on the bug.
- **Afterglow flags, sky1 → sky2:** 162 shared, 62 gone (36 tier E, 12 D, 11 C, 3 B; none tier A), **152 new**. All three
  sky1 tier-A flags (incl. ASASSN-21qj and OS-0014) are still flagged.
- **The 152 new flags through `hunt_h0002_vet.py sky2new`:** 101 E (no parallax), 23 C (dust before 2010), 22 D (blend or
  pair), 7 B (all hot stars, BP-RP -0.24 to +0.33 and M_G -3.1 to +1.0: the Be-star-disk class H-0002 already set aside),
  **1 A**: AllWISE 2093118101351034127 = Gaia DR3 1244878889014096256 (G 13.66, Teff 6021 K, logg 4.50, 713 pc), flat in
  W1/W2 for ten years, then W2 +0.29 and W1-W2 +0.12 redder on both 2024 visits.
- **That tier-A flag is an impostor.** IRSA was down, so the centroid test was done on the raw NEOWISE Parquet
  (`scripts/hunt_h0002_centroid_raw.py 2093118101351034127 2211 209.1123 18.1975 209.1132 18.1967`): along the line to a G = 20.0, parallax-free source 4.22" away, the per-visit
  centroid sat at 0.24-0.46" for 2014-2023 and jumped to 0.90-0.92" in both 2024 visits, as expected if the added W2 light
  comes from the neighbour (≈ 0.24 of the flux at 4.2" → ≈ 0.6-1.0"). A background galaxy or AGN flared; the star did not.
- **Net: the fixed sky adds no new afterglow survivor.** H-0002's conclusion (two survivors, OS-0013 and OS-0014) now holds
  on 35% more photospheres than it originally tested, which makes it a stronger negative result.
- Second float bug found on the way: `hunt_h0002_vet.py` read `source_id` from a mixed-dtype row (float64), rounding it onto
  a neighbouring id (…096384 for …096256) and comparing the rounded id in the blend check. Fixed (int64 column). sky1's
  `vetted.parquet` was built with it; its tier assignments should be re-checked if anyone relies on its blend counts.
